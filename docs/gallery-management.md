# 相册管理

进入 `/admin/`，使用管理员账号登录，选择「相册管理」。

1. 新建相册，填写名称、标识、描述、拍摄日期、地点和标签。
2. 批量上传照片、从图片素材库选择，或填写 HTTPS / 站内图片地址。
3. 编辑每张照片的说明，用上下按钮调整照片顺序，选择封面。未指定封面时使用第一张照片。
4. 勾选「发布到前台」后保存；未勾选时保存为草稿，仅管理员可见。
5. 在 `/gallery/` 查看、搜索和筛选已发布相册。详情链接为 `/gallery/?album=<相册标识>`，可直接分享，刷新和浏览器前进后退均可使用。

相册显示顺序数字越小越靠前；顺序相同则新建相册靠前。
前台照片按原始比例以瀑布流展示，随内容区域宽度自动切换2–5列；相册列表使用带书脊细线和叠页边框的封面卡片。
每个相册最多500张照片，每张上传图片最多8 MiB。素材上传使用现有管理员图片接口。
移除照片或删除相册只删除关联记录，素材文件仍保留；如需永久删除文件，请在图片素材库操作。
草稿不出现在公开接口中，但已上传图片本身仍是公开资源，草稿不提供图片文件的私密存储。

## 启动与部署

本功能同时包含前端和 `backend/` 中的 Rust 后端修改。更新后端代码后重新构建并重启服务（开发环境可在 `backend/` 目录执行 `cargo run`）；启动时会自动创建 `gallery_albums` 表。
前端首次部署这次代码需要运行 `pnpm build`。之后在后台添加或修改相册无需再次构建前端。
现有 `src/config/galleryConfig.ts` 和 `public/gallery/` 用于旧版本地静态相册详情页，不会自动导入后台；当前仓库本地相册配置为空。

## 接口

- `GET /api/v1/gallery/albums`：仅返回已发布相册，包含按顺序排列的照片。
- `GET /api/v1/admin/gallery/albums`：管理员读取全部相册。
- `POST /api/v1/admin/gallery/albums`：管理员新建。
- `PUT /api/v1/admin/gallery/albums/{id}`：管理员编辑。
- `DELETE /api/v1/admin/gallery/albums/{id}`：管理员删除。

所有写入由管理员权限保护；后端校验相册标识唯一性、图片地址、日期、字段长度和照片数量。
